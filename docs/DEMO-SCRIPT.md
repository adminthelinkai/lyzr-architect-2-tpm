# Three-minute platform demo

Use a clean browser or reset the local demo. Explain upfront: Architect 2.0 is a live UI/UX prototype with functional local state and labeled external-service simulations.

| Time | Action | Narration |
| --- | --- | --- |
| 0:00–0:25 | Show homepage and templates; create a sales-lead app | “Architect 2.0 is a general-purpose app-building platform. A business user can start with an idea; a developer can bring an existing project. The template supplies an editable starting point.” |
| 0:25–0:50 | Approve plan; inspect sales agents; build board | “This project has lead-specific roles, records and stages. The outcome owner and developer share one configuration.” |
| 0:50–1:15 | App structure; change fields or layout; add an agent | “The application structure is editable. I can define my own data, workflow and agent contracts. Research uses briefs, support uses an inbox, and custom starts blank.” |
| 1:15–1:45 | Request Add Teams alerts; review impact; apply and undo | “One request affects the interface, an agent's tools and a permission. The user sees the consequences before applying. Undo restores the coupled configuration; tests are tied to a revision.” |
| 1:45–2:05 | Grant sample connections; test; failed release then retry | “Missing permissions block release. Failure preserves the project and offers recovery. This internal deployment is simulated; the platform website is live.” |
| 2:05–2:35 | Import research manifest; technical view; inspect contracts | “Developers see file entries, dependencies and missing configuration. Frameworks describe contracts here; real repository cloning and executable adapters are future work.” |
| 2:35–3:00 | Edit config; switch guided view; show GitHub conflict and release checks | “Both views use the same project. Technical ownership remains visible through configuration, source controls and revision-based release evidence.” |

For an extended demo, create an unfamiliar idea with **Custom**. Set labels, fields and stages, add an agent, add a record, move it and reload. This proves the app-building controls work beyond the supplied examples.

Invite discussion: which project assumptions should the platform clarify, which edits deserve impact review, and what evidence should block a real release? Personal industry experience can inform a test case; it does not define the platform's scope.
