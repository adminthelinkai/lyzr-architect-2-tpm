# Three-minute demo script

Before recording: use a clean browser or Settings → Reset demo. Keep one tab ready on the homepage. Speak honestly: this is a working local-state product prototype; external services are simulated. Avoid showing real customer data.

| Time | Action | Narration |
| --- | --- | --- |
| 0:00–0:20 | Open reviewer demo; show outcome plan | “I chose an EPC quality workflow because it connects to my stated industry background. The product hypothesis is a shared application that a business owner and developer can both inspect.” |
| 0:20–0:40 | Approve plan, show agents, Build preview | “The plan asks who reviews uncertainty. Three roles classify, retrieve evidence, and draft a handoff. A qualified person remains accountable.” |
| 0:40–1:10 | Request Add Teams alerts; inspect Change impact; Apply; Undo; apply again | “This is the main interaction: one request changes the interface, a tool permission, and release readiness. The user sees that before applying. Undo restores the coupled configuration.” |
| 1:10–1:35 | Data: grant knowledge; deny Teams then reconnect; Test release suite | “A connection is more than a green badge. Denial creates a blocker and tells me what permission I need. Tests belong to the current revision.” |
| 1:35–1:50 | Release; choose health-check timeout; deploy; Retry healthy release | “A failed health check creates no active release. Retry records a versioned snapshot. This publishing flow is simulated; the prototype website itself is hosted.” |
| 1:50–2:15 | Overview → Import → Load sample → inspect; Technical → Files & config | “The developer can bring an existing project manifest and inspect its entrypoints and missing model configuration. This is not a real clone. Framework choices are inspectable contracts, not an unimplemented compatibility claim.” |
| 2:15–2:40 | Edit reviewBelow to 90; Review diff; Apply; switch Guided | “Configuration changes use the same review path as chat. The guided preview now uses 90 percent. There is no second project hidden behind the mode switch.” |
| 2:40–3:00 | GitHub → authorize sample → simulate conflict → choose local; show Release checks | “Source ownership, conflict decisions, and release evidence stay visible. A developer can continue using their coding tool while the business owner reviews intent here. Next I would validate whether this reduces handoff errors before adding real adapters.” |

The developer's complete release path takes another 30–45 seconds: connect knowledge and the sample model, sync GitHub, pass the release suite, and deploy. Both complete journeys are automated in the repository even though this short narration focuses on the distinguishing decisions.
